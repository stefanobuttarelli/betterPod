## Implemented and checked locally

The paired and discovered-device rows referenced `bt_headphones`, but that
asset was neither present in the package nor generated by the loader. The
renderer therefore had no image to draw. All devices also used that same key.

Five original Go glossy tiles are now generated and uploaded before the UI
loop: headphones, earbuds, speaker, game controller and generic Bluetooth.
They are rasterized at 192x192 for the native 96x96 row slot. Classification
uses the device name and BlueZ `Icon`, preserving the original precedence and
Unicode lowercasing. The Sony WH-1000XM6 selects the headphone tile. No file
read, icon rasterization or device classification was added to frame drawing.

The source audit also found that the output-routing retry loop stopped on its
first failed `pactl list` call. A temporary Pulse/PipeWire failure now consumes
only one probe. Subsequent probes, output selection and sleeps share the
remaining eight-second budget and the sixteen-attempt limit. Unrelated sinks
never change the output. The existing Connect success/logging behavior is
preserved.

The explicit local diagnostic snapshot now includes native audio callback,
rate, chunk and PCM-underrun counters, plus each row's icon name. This permits
screen-off audio observations without enabling per-frame rendering or disk
writes. Diagnostics remain disabled in ordinary launches.

Validation: **280 ordinary tests pass** (207 library, 67 app, 6 proxy),
including the new device-class/raster and paired/discovered-row regressions.
Seven Bluetooth unit tests cover retry recovery, timeout-budget exhaustion,
unmatched sinks, address validation, battery parsing and structured routing.
All five exported rasters were visually compared with the Go source.
