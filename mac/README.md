# betterPod Share for Mac

The Mac app has three independent workspaces: **Library** edits local audio files, **betterPod** edits the experimental Rust player's library over local Wi-Fi, and **Share** sends songs and albums with an 8-digit code. Library works without a connected betterPod or a share code.

## Local library

1. In **Library**, open an album folder or audio files with **Open** (⌘O), or drop them on the window. Folders include their subfolders.
2. Select an album's tracks, or several albums, and choose **Find Album** (⌘F). With nothing selected it uses the visible tracks. It searches MusicBrainz, Discogs, iTunes, Deezer and Wikipedia (English and Italian) with the folder name, tags, filenames, numbering and track count, compares the editions' track lists and selects the strongest match. Folder suffixes such as `[FLAC]`, codec details and catalog numbers are cleaned before searching. Discogs searches CD editions first, whose numbering and lengths match ripped files. To use one exact edition, paste its Discogs link into the Album field.
3. The preview shows the cover, album details and track pairings. **Cover**, **Album details** and **Track names and numbers** are applied together unless you clear them; track names are paired only when the edition has as many tracks as the selection. Choose another match or source, or refine the search, before applying. With several albums, Find Album works one album at a time: **Apply and Next** or **Skip Album**.
4. Review the changes in the table. Each changed field and cover has an **Edited** marker; after saving it has a **Saved** marker. The **Changes** filter shows both. Hover a field to see its previous value. **Save Changes** (⌘S) writes every changed loaded track, including tracks hidden by the album filter. Find Album prepares drafts; it never writes files by itself.
5. The inspector edits title, artist, album, album artist, genre, year, disc and track numbering for every editable selected track. Shared fields show **Multiple Values** when they differ. Choose a JPEG or PNG cover, drop one on the cover, remove it, or **Revert Unsaved Changes**. The context menu and the Library menu also offer **Merge into Album…**, which gives selected tracks the destination's album identity without moving files or replacing song titles. If the destination lacks an album artist, Merge fills it consistently for the destination and incoming tracks, using its sole performer or **Various Artists**. Albums with the same normalized album and album-artist tags group together across folders. Missing album artists use performer and folder context to keep unrelated albums with the same title apart. Untagged albums use their folder identity; CD/Disc subfolders share the album parent.
6. The table initially sorts by artist → album → disc → track, with natural filename ordering for missing numbers. Click any column heading to sort ascending or descending. **Remove from Library** (⌘⌫) and **Clear Library** remove items from the current view only; the files stay on disk. **Undo Library Removal** restores the removed items and their drafts. The app asks before discarding unsaved edits when opening other files or closing.

MP3, FLAC, Ogg Vorbis and M4A support editing. WAV and AIFF can be viewed only; unsupported or unsafe metadata layouts also show a read-only reason. Manual editing works offline. Online identification sends search text derived from folder names, tags and filenames to the music catalogs and Wikipedia, and downloads metadata and artwork. Audio files are never uploaded. No account or API key is needed; Discogs allows about 25 searches a minute without one, so the app keeps a margin and leaves the other sources working.

Each file is staged beside its original and replaced only after a successful write. Audio and unrelated tags are preserved. A file changed outside the app since opening is refused so it can be reloaded. A batch can partly succeed: successfully saved files refresh, each failure is listed, and failed drafts remain available for correction. Symlinked files are not overwritten.

The local editor remains independent from connected devices. Its files stay on the Mac.

## betterPod over Wi-Fi

This requires the experimental Rust player with Wi-Fi Library support. The classic player and its Share protocol are unchanged.

1. On betterPod Rust, open **Music → Wi-Fi Library** (also available in Settings), then **Start Connection**. It shows a fresh eight-digit code.
2. On the Mac, open **betterPod**, choose **Find betterPod**, select the player and enter its code. Both devices must use the same local network. If discovery is blocked, expand **Enter a local address** and enter the IP address and port shown on the player.
3. Browse the library, filter it by album, and select one or several tracks. The same artist → album → disc → track order, sortable columns, tag editor, cover controls and **Find Album** work here. **Merge into Album…** and the album grouping that Find Album stages work with a current Rust player that advertises album joining support. Older players keep tag and cover editing and show an update notice. Audio files remain on the player; cover previews load when selected.
4. Use Find Album or the inspector, review the highlighted draft and choose **Save Changes** in the header. Metadata, artwork and album membership are written on betterPod and its library refreshes automatically. Joining works across physical folders without moving audio or changing disc numbers. **Album Grouping** has its own Edited/Saved marker; a join remains pending if betterPod saved tags but could not confirm the grouping. Plain Album or Album artist edits clear a conflicting private grouping, while cover edits clear a conflicting chosen cover.
5. Choose **Disconnect** in the Mac's header or **Stop Connection** on betterPod. Leaving the player page keeps an active connection available. Closing betterPod, moving its music/database, or starting a file transfer revokes it.

No connection starts at launch. Pairing and encrypted traffic run directly on the LAN without a relay, account or audio upload. Codes expire after ten minutes; connected sessions end after thirty minutes of inactivity or eight hours. Only one Mac can connect at a time. Five unsuccessful pairing attempts require starting a new connection.

The current decoder's track, including a paused track, cannot be changed remotely. Select another track or stop playback and refresh. A changed file is refused until reloaded. Interrupted saves are never automatically retried: reconnect and reload first, since a batch may already have been written. Partial failures keep their unsaved drafts. Selecting local files while in the betterPod workspace opens them in the separate local Library editor.

See [the Rust Wi-Fi Library notes](../rust/WIFI_LIBRARY.md) for the protocol and local verification workflow. No build is deployed or published automatically.

## Share

**Share** sends songs and albums from a Mac to a betterPod with an 8-digit code, as a betterPod's own Share does (see [NOTES.md](NOTES.md) for how it is used). It only sends; a betterPod receives with Music → Receive. Its studio background fills the window when resized while the transfer scene stays centered.

How songs travel: one album (or some of its songs) goes as the console sends one; one song shows its title on the betterPod; songs of several albums go with one code, in a folder "From <name>" with a subfolder per album, each with its cover, and a collage of the covers on the betterPod's screen.

## Development

- `core/`: the engine, in Go. The share path reads songs (tags, covers), groups them by album and sends them with magic-wormhole (the vendored wormhole-william, app id `betterpod.xyz/share`). It is the same protocol as `src/ij_share.go`; keep the two in step. The separate `library*.go` files read and safely write local metadata and artwork without starting a share. Built as a C archive for the app; `go run ./mac/core <files…>` sends from the command line, for tests (`BETTERPOD_WORMHOLE_URL`, `BETTERPOD_WORMHOLE_RELAY`, `BETTERPOD_SHARE_CODE`, `BETTERPOD_SHARE_FROM`).
- `App/`: the app, in SwiftUI (macOS 13+). `PodDesign.swift` is its design system: the console's glossy header and blue selection cursor (`src/ij_theme.go`, `src/ij_views.go`), the Share studio's greys, glossy buttons, cards and a fixed source list, with light and dark variants. Surfaces are drawn rather than translucent, so the app looks the same on every macOS version; tables, fields and menus stay native. The window draws its own header (hidden title bar): title in the middle, as on the console, and only Open, Find Album and Save on the right. Increased contrast and reduced motion are respected. Share keeps the console's studio, pedestal, laser and digit tiles in a window-filling scene. `AlbumLookup.swift` searches the [MusicBrainz API](https://musicbrainz.org/doc/MusicBrainz_API), follows its [request limits](https://musicbrainz.org/doc/MusicBrainz_API/Rate_Limiting), and supports iTunes and Deezer metadata and artwork. MusicBrainz covers use the [Cover Art Archive API](https://musicbrainz.org/doc/Cover_Art_Archive/API). `AlbumLookupDiscogs.swift` uses the [Discogs API](https://www.discogs.com/developers) without a token, and `AlbumLookupWikipedia.swift` reads album infoboxes and track listings from English and Italian Wikipedia articles through the [MediaWiki API](https://www.mediawiki.org/wiki/API:Main_page); Italian Wikipedia has no covers, so another source supplies them.
- `App/Updater.swift`: the app updates itself, as Software Update does on the consoles. At start (and from App → Check for Updates…) it looks for the newest `mac-v…` release on GitHub; Update downloads its zip, checks its size and SHA-256 (the digest GitHub gives for each release file), unpacks it, checks its signature, puts it in place of the app and starts it. So the zip keeps its name, `betterPod-Share-mac-v<version>.zip`. When the app can't replace itself (opened from Downloads, where macOS runs a copy, or in a folder it can't write to), it offers the release's page instead.
- `build.sh`: builds it on a Mac (Go and Xcode's command line tools): a universal app, signed ad hoc (not notarized: macOS asks before the first launch), and its zip.
- `VERSION`: the app's version. `.github/workflows/mac.yml` builds it on each change and makes the GitHub release `mac-v<version>` with `NOTES.md`. A version such as `1.1-beta.1` becomes a prerelease: the updater offers prereleases only to a beta, and a beta comes before its final version. To publish a beta without merging, run the workflow on its branch (`gh workflow run mac.yml --ref <branch>`).
- `tests/check.sh`: runs local Go metadata tests, builds a temporary C archive, and runs Swift lookup and editor-model checks. It requires Go and Xcode's command line tools on `PATH`. Run `sh mac/tests/check.sh` from the repository. Network replies in the lookup checks are fixtures; the checks do not contact online services or publish anything. All temporary build output is removed afterward.
- `tests/check-wifi.sh`: runs the real Rust server against the Mac's Go client on localhost, using disposable audio fixtures. It requires the existing Rust Mac build dependencies and never opens a real music library.

The existing release and updater flow is unchanged. Local development and checks do not create or publish a release.
